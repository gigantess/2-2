## 3. 개선 목표

### 3.1 기능 안정성
- LLM 응답의 구조·타입·빈 값 검증을 강화한다.
- 장소 검색 시 입력 정규화와 fallback 로직을 추가해 추천 실패율을 낮춘다.
- 외부 API 오류는 재시도/백오프/로그 기준에 따라 안정적으로 처리한다.

### 3.2 운영 신뢰성
- 결과 파일 저장 실패를 방지하기 위해 원자적 저장 전략을 적용한다.
- 캐시 갱신 정책과 강제 새로고침 옵션을 명시해 재실행 시 일관성을 확보한다.
- 에러를 구조화하여 분석 가능성을 높인다.

### 3.3 사용자 경험
- CLI 도움말과 오류 메시지를 명확하게 한다.
- 검색 결과 0건 및 실패 상황에 대해 대체 옵션을 제공한다.
- 문서에 아키텍처와 예시를 추가해 유지보수성과 이해도를 높인다.

### 3.4 보안
- 결과 파일 및 로그에 노출될 수 있는 API 키 패턴을 사전에 차단한다.
- 운영 환경에 맞는 비밀관리 연계를 권장한다.

## 4. 구체적 개선 계획

### 4.1 LLM 응답 검증 강화

#### 변경 대상
- `llm_client.py`

#### 개선 내용
- 응답 JSON의 필수 키를 단순 존재 확인에서 구조적 검증으로 개선한다.
- 기대 타입을 명시한다.
  - `recommended_city`: string
  - `weather`: string
  - `events`: list
  - `reason`: string
- 필드별 유효성 규칙을 추가한다.
  - 빈 문자열 금지
  - `events`는 비어 있으면 안 됨
  - 각 event 문자열은 공백 제거 후 길이가 1자 이상이어야 함
  - 최소 길이/최대 길이 기준을 정의해 비정상 값 차단
- 검증 실패 시 예외를 발생시키고, 기존 재시도 로직이 정상적으로 동작하도록 한다.

#### 기대 효과
- 비정상 LLM 응답으로 인한 후속 에러를 줄인다.
- 추천 결과의 품질을 안정적으로 유지한다.

---

### 4.2 입력 도시명 정규화 및 검색 보정

#### 변경 대상
- `place_client.py`

#### 개선 내용
- `normalize_city_name(city: str) -> str` 함수를 추가한다.
- 별칭 및 표기 차이를 정규화한다.
  - `제주도 -> 제주`
  - `서울특별시 -> 서울`
  - `부산광역시 -> 부산`
  - `강원도 강릉시 -> 강릉`
- 행정구역 수식어를 제거한다.
  - 특별시, 광역시, 특별자치도, 도, 시, 군 등
- 검색 결과가 비어 있으면 fallback 전략을 수행한다.
  - `도시명 맛집` → `도시명 대표 맛집` → `광역시/도 수준 키워드` 순으로 재검색
- 입력값이 없거나 이상할 때는 사용자에게 의미 있는 에러 문구를 반환한다.

#### 기대 효과
- 추천 도시 검출의 일관성이 높아지고, 실제 검색 성공률이 향상된다.
- 별칭/표기 차이에 따른 결과 누락을 줄인다.

## 6. 검증 기준

다음 항목을 기준으로 개선이 성공했는지 확인한다.

1. LLM 응답에서 `events`가 배열이 아니거나 비어 있으면 재시도 및 예외 처리가 발생한다.
2. `제주특별자치도`, `서울특별시`, `강원도 강릉시`와 같은 입력이 정상적으로 정규화된다.
3. 검색 결과가 비어 있을 때 fallback 검색이 동작한다.
4. 실패 케이스별 로그와 에러 메타데이터가 정상 저장된다.
5. 결과 파일 저장 시 임시 파일 기반 안전 저장이 적용된다.
6. 캐시가 만료되면 자동 갱신 또는 강제 새로고침 옵션이 동작한다.
7. README 및 CLI 문서를 통해 사용자가 직접 문제를 해결할 수 있다.

위 보완을 완료하면 프로젝트는 다음과 같은 수준으로 발전한다.

- LLM 응답 품질 검증이 강화되어 예측 불가능한 데이터 오류 감소
- 외부 API 연동 안정성이 높아져 장애 대응 속도 향상
- 사용자 경험과 운영 편의성이 개선됨
- 보안·캐시·파일 저장 측면의 안정성 확보
- 문서와 코드의 유지보수성이 향상됨

결론적으로, 이번 개선 계획은 미통과 항목 해결을 최우선으로 하되, 통과 항목의 보완 권장사항까지 포함해 전체 평가 점수를 100%에 가깝게 끌어올리는 데 초점을 둔다.
